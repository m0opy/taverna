# «Таверна» — требования к MVP

Хаб для ДнД-кампании: участники, заметки сессий, NPC, дата следующей игры.

Документ фиксирует объём MVP, поведение всех экранов и крайние случаи. Всё, что не описано здесь, — вне MVP.

---

## 1. Термины

| Термин | Значение |
|---|---|
| Пользователь | Аккаунт (имя, email, пароль) |
| Кампания | Игровая группа со своим контентом. Создатель = мастер |
| Участник (membership) | Связь пользователя и кампании + данные его персонажа |
| Персонаж | Имя и описание, которое участник задаёт при вступлении |
| Мастер | Создатель кампании, ровно один, не меняется |
| Игрок | Любой участник, кроме мастера |
| Инвайт-ссылка | Постоянная ссылка вида `/join/:token`, по ней вступают в кампанию |

---

## 2. Роли и права

Ролей ровно две, они не настраиваются в интерфейсе. Мастер определяется полем `Campaign.ownerId`; любой другой активный участник кампании — игрок. Поле роли в `Membership` не хранится.

| Действие | Мастер | Игрок |
|---|:--:|:--:|
| Просматривать все разделы кампании | ✅ | ✅ |
| Создавать заметки и NPC | ✅ | ✅ |
| Редактировать/удалять **свою** заметку | ✅ | ✅ |
| Редактировать/удалять **чужую** заметку | ✅ | ❌ |
| Редактировать/удалять любой NPC | ✅ | ✅ |
| Редактировать свои данные персонажа | ✅ | ✅ |
| Менять название, сюжет, обложку кампании | ✅ | ❌ |
| Ставить дату следующей сессии | ✅ | ❌ |
| Видеть и перегенерировать инвайт-ссылку | ✅ | ❌ |
| Исключать участников | ✅ | ❌ |
| Удалить кампанию | ✅ | ❌ |
| Выйти из кампании | ❌ | ✅ |

**Решение по NPC:** NPC — общая база знаний партии, любой участник правит любую карточку. Это осознанное упрощение: разграничение прав на NPC не стоит потраченного времени, а в реальной игре записи всё равно ведутся коллективно.

**Решение по мастеру:** передача прав мастера вне MVP. Мастер не может выйти из кампании — только удалить её целиком.

## 3. Сущности и поля

### User
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `name` | string | 2–40 символов, обязательное |
| `email` | string | валидный email, уникальный, хранится в нижнем регистре |
| `passwordHash` | string | argon2 |
| `createdAt` | datetime | |

### Campaign
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `title` | string | 2–60 символов, обязательное |
| `synopsis` | text | 0–500 символов |
| `coverKey` | string | один из 6 пресетов (`forest`, `dungeon`, `tavern`, `sea`, `mountains`, `city`) |
| `inviteToken` | string | 12 символов, url-safe, уникальный |
| `nextSessionAt` | date? | календарный день без времени, null допустим |
| `ownerId` | uuid | FK → User; единственный источник истины о мастере |
| `createdAt` | datetime | |

**Обложка:** пресеты вместо загрузки файла. Загрузка изображений — вне MVP, экономит день работы на аплоаде и хранилище.

### Membership
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `userId`, `campaignId` | uuid | FK → User, Campaign; одновременно может существовать не более одного активного membership для пары |
| `characterName` | string? | 2–40 символов; обязательно для игрока при вступлении, у мастера может быть null |
| `characterClass` | string? | 0–60 символов («Полурослик-плут», свободный текст) |
| `characterInfo` | text? | 0–300 символов, «о себе» от лица персонажа |
| `joinedAt` | datetime | |
| `leftAt` | datetime? | null у активного участника; заполняется при выходе или исключении |

**История участия:** membership не удаляется при выходе или исключении, потому что на него ссылаются заметки и NPC. Новый вход после выхода создаёт новую запись. Ограничение «не более одного активного membership на пару `userId + campaignId`» обеспечивается частичным уникальным индексом `WHERE leftAt IS NULL` в SQL-миграции и проверкой в транзакции сервиса. Все списки участников и проверки доступа учитывают только записи с `leftAt IS NULL`.

**Роль мастера:** `Campaign.ownerId` — единственный источник истины. При создании кампании владелец и его membership создаются в одной транзакции. Мастер не может выйти, поэтому его membership остаётся активным до удаления кампании.

### Note
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `campaignId`, `authorId` | uuid | `authorId` → Membership; membership автора не удаляется физически |
| `body` | text | 1–5000 символов, обязательное |
| `sessionDate` | date? | опциональная привязка к дате игры |
| `createdAt`, `updatedAt` | datetime | |

**Решение:** отдельной сущности «Сессия» нет. Заметки группируются по `sessionDate`; заметки без даты попадают в группу «Без сессии». Это убирает целую таблицу и экран управления сессиями.

### Npc
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `campaignId`, `createdById` | uuid | `createdById` → Membership; membership автора не удаляется физически |
| `name` | string | 1–60 символов, обязательное |
| `title` | string | 0–60 символов (роль, «Трактирщик») |
| `attitude` | enum | `ally` / `neutral` / `enemy` / `unknown`, по умолчанию `unknown` |
| `tags` | string[] | до 5 тегов, каждый 1–24 символа |
| `notes` | text | 0–1000 символов |
| `createdAt`, `updatedAt` | datetime | |

### NpcRelation
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | uuid | |
| `fromNpcId`, `toNpcId` | uuid | оба в одной кампании, `from ≠ to` |
| `label` | string | 1–60 символов («брат», «должен денег») |

Связь односторонняя и до 5 штук на карточку. На карточке-цели связь не отображается — это осознанное упрощение, двусторонняя синхронизация вне MVP.

### Лимиты
- До 10 участников в кампании.
- До 20 кампаний у пользователя.
- До 200 NPC и до 500 заметок в кампании.

Лимиты нужны как защита от мусора, а не как продуктовая механика. При достижении — понятная ошибка, апселла нет.

## 4. Ключевые сценарии

### 4.1 Регистрация и первая кампания
1. Гость на `/` → лендинг с описанием и кнопками «Войти» / «Зарегистрироваться».
2. Регистрация: имя, email, пароль. После успеха — автоматический вход и редирект на `/campaigns`.
3. Дашборд пуст → пустое состояние с кнопкой «Создать кампанию».
4. Форма создания: название, сюжет (опц.), выбор обложки → редирект на `/c/:id`.
5. На главной кампании мастер видит блок с инвайт-ссылкой и кнопкой «Скопировать».

Мастер при создании кампании **автоматически становится активным участником**, но данные персонажа у него могут быть пустыми. На главной ему показывается плашка «Заполните персонажа» со ссылкой на модалку — мастер может играть за NPC и не иметь персонажа, поэтому плашка закрывается и не блокирует работу. При пустом `characterName` в списке участников он отображается как «Мастер» без имени персонажа.

### 4.2 Вступление по ссылке
1. Пользователь открывает `/join/:token`.
2. Не авторизован → экран приглашения (название кампании, обложка, число участников, имя мастера) с кнопками «Войти» / «Зарегистрироваться». Токен сохраняется, после авторизации — возврат на `/join/:token`.
3. Авторизован и ещё не участник → форма персонажа: имя персонажа (обязательно), класс/раса (опц.), «о себе» (опц.). Кнопка «Вступить».
4. После вступления — редирект на `/c/:id` с тостом «Вы вступили в кампанию».

### 4.3 Ведение кампании
- Игрок открывает раздел «Заметки», нажимает «Написать заметку», вводит текст и опционально выбирает дату сессии.
- Игрок открывает «NPC», добавляет карточку, задаёт отношение и теги. Теги вводятся с автоподсказкой из уже существующих в кампании.
- Мастер на главной ставит дату следующей сессии.

## 5. Экраны

Общая оболочка авторизованного пользователя: шапка с логотипом (ведёт на `/campaigns`), справа — имя пользователя и «Выйти».

### 5.1 `/` — лендинг
Для гостя: название, одно предложение о продукте, скриншот-заглушка, кнопки «Войти» и «Зарегистрироваться». Авторизованного сразу редиректим на `/campaigns`.

### 5.2 `/register`, `/login`
Центрированная карточка. Поля, кнопка сабмита, ссылка на противоположный экран. Ошибки — под полем, общая ошибка сервера — над кнопкой. Сабмит блокируется на время запроса (спиннер в кнопке).

### 5.3 `/campaigns` — дашборд
Заголовок «Ваши кампании» + кнопка «Создать кампанию». Сетка карточек: обложка, название, число участников, роль («Мастер» / «Игрок»), дата следующей сессии или «Дата не назначена».

Пустое состояние: иллюстрация-заглушка, «Создайте первую кампанию», подпись «Или попросите мастера прислать ссылку-приглашение», кнопка.

### 5.4 `/campaigns/new`
Форма в одну колонку: название, сюжет (textarea со счётчиком символов), выбор обложки (6 плиток, выбранная с рамкой). Кнопки «Создать» и «Отмена».

### 5.5 `/join/:token`
Три состояния, описаны в 4.2 и в разделе 6.

### 5.6 `/c/:id` — главная кампании
Оболочка кампании: шапка с названием кампании, выпадающий переключатель кампаний, табы `Главная · Заметки · NPC`, у мастера дополнительно иконка настроек.

Контент главной:
- Баннер с обложкой, названием и сюжетом.
- Блок «Следующая сессия»: дата, день недели, «через N дней». У мастера — кнопка «Изменить», у игрока только текст. Если не назначена: «Дата не назначена», у мастера — кнопка «Назначить».
- Список участников: карточка на каждого — инициалы, имя персонажа, класс/раса, бейдж «Мастер», ниже «о себе». Под именем персонажа мелко — имя пользователя.
- У мастера: блок «Пригласить игроков» с полем ссылки (только чтение), кнопками «Скопировать» и «Обновить ссылку».

### 5.7 `/c/:id/notes`
Кнопка «Написать заметку» открывает форму (инлайн сверху или модалка): textarea, поле даты сессии с чекбоксом «Привязать к сессии», кнопки «Опубликовать» / «Отмена».

Лента сгруппирована по `sessionDate` по убыванию, внутри группы — по `createdAt` по убыванию. Заголовок группы: «Сессия 3 августа» или «Без привязки к сессии». Карточка заметки: инициалы автора, имя персонажа автора, относительное время («2 дня назад»), текст, у автора и мастера — иконки «Изменить» и «Удалить». У изменённой заметки — пометка «изменено».

Пустое состояние: «Пока нет ни одной заметки», «Запишите, что произошло на последней сессии», кнопка.

### 5.8 `/c/:id/npc`
Шапка: «NPC · N», кнопка «Добавить NPC». Строка фильтров: чипсы «Все» + все теги кампании; выбранный чипс подсвечен. Фильтр по одному тегу за раз, выбор второго заменяет первый.

Сетка карточек (макет уже согласован): инициалы, имя, титул, чипсы отношения и тегов, текст заметки (обрезается на 3 строках), внизу — связи или «без связей».

Форма NPC (модалка): имя, титул, отношение (сегментированный контрол из 4 значений), теги (инпут с добавлением по Enter и автоподсказкой), заметки, блок связей — строка «NPC из списка + описание», кнопка «Добавить связь» (до 5).

Пустое состояние: «Здесь появятся NPC», «Записывайте, кого встретила партия, — потом не вспомните», кнопка.

### 5.9 `/c/:id/settings` — только мастер
Секции:
1. Основное: название, сюжет, обложка, кнопка «Сохранить».
2. Приглашение: ссылка, «Скопировать», «Обновить ссылку» (с подтверждением: старая перестанет работать).
3. Участники: список с кнопкой «Исключить» у каждого, кроме себя.
4. Опасная зона: «Удалить кампанию» — модалка с вводом названия кампании для подтверждения.

Игрок при переходе на `/c/:id/settings` получает 403-экран. У игрока есть отдельная кнопка «Покинуть кампанию» в меню пользователя внутри кампании, с подтверждением.

### 5.10 Модалка персонажа
Открывается при вступлении и при редактировании своих данных. Поля: имя персонажа, класс/раса, о себе.

## 6. Крайние случаи

### Авторизация
| Ситуация | Поведение |
|---|---|
| Регистрация с занятым email | Ошибка под полем: «Такой email уже зарегистрирован» + ссылка «Войти» |
| Email в другом регистре | Приводим к нижнему регистру, считаем тем же аккаунтом |
| Неверная пара email/пароль | Общая ошибка «Неверный email или пароль» — не уточняем, что именно неверно |
| Пароль короче 8 символов | Валидация на клиенте и на сервере |
| Истёк JWT | 401 от API → редирект на `/login` с тостом «Сессия истекла, войдите снова» и сохранением адреса возврата |
| Открыт защищённый адрес без авторизации | Редирект на `/login?next=<адрес>`, после входа — возврат |
| Пользователь уже авторизован и открыл `/login` | Редирект на `/campaigns` |

### Инвайт
| Ситуация | Поведение |
|---|---|
| Токен не существует или устарел | Экран «Приглашение недействительно», подпись «Попросите мастера прислать новую ссылку», кнопка на дашборд |
| Пользователь уже участник этой кампании | Сразу редирект на `/c/:id` с тостом «Вы уже в этой кампании» |
| Мастер открыл ссылку своей кампании | То же самое — редирект на кампанию |
| В кампании 10 участников | Экран «В кампании нет свободных мест» |
| Пользователь вступил в свою же кампанию под другим аккаунтом | Разрешено, это обычный участник |
| Мастер обновил ссылку, пока игрок был на экране вступления | Игрок получит ошибку недействительного приглашения при сабмите |

### Кампания и участники
| Ситуация | Поведение |
|---|---|
| Не участник открыл `/c/:id` | 403-экран: «У вас нет доступа к этой кампании», кнопка на дашборд. Не 404 — путать пользователя не нужно |
| Кампания удалена, у пользователя открыта её страница | Ближайший запрос вернёт 404 → редирект на дашборд с тостом «Кампания удалена» |
| Мастер исключил участника | У membership заполняется `leftAt`; запись физически не удаляется. Заметки и NPC исключённого **остаются**, авторство сохраняется как имя персонажа из исторического membership. Требуется подтверждение с текстом «Заметки останутся в кампании» |
| Исключённый участник вступает заново по ссылке | Разрешено: создаётся новый активный membership, пользователь снова заполняет персонажа. Исторический membership остаётся связан со старым контентом |
| Игрок вышел из кампании | У membership заполняется `leftAt`, как при исключении, но по инициативе самого игрока |
| Мастер пытается выйти | Кнопки нет; в настройках вместо неё — «Удалить кампанию» |
| Удаление кампании | Каскадно удаляются активные и исторические membership, заметки, NPC и связи |
| Два участника с одинаковым именем персонажа | Разрешено, уникальность не проверяем |

### Даты сессий
| Ситуация | Поведение |
|---|---|
| Дата в прошлом | Разрешаем, но на главной вместо «через N дней» показываем «Сессия прошла». Мастер сам решит, когда обновить |
| Сессия сегодня | «Сегодня» вместо «через 0 дней» |
| Дата сессии заметки в будущем | Разрешаем — можно писать план на следующую игру |
| Часовые пояса | `nextSessionAt` и `sessionDate` хранятся как PostgreSQL `date` без времени и не преобразуются между часовыми поясами; формат отображения берётся из локали браузера |

### Заметки
| Ситуация | Поведение |
|---|---|
| Пустой текст или только пробелы | Кнопка публикации неактивна |
| Превышение 5000 символов | Счётчик становится красным, сабмит блокируется |
| Автор исключён из кампании | Заметка и исторический membership остаются; автор подписан сохранённым именем персонажа без ссылки |
| Одновременное редактирование | Побеждает последний сохранивший. Блокировки и версионирование вне MVP |
| Переносы строк в тексте | Сохраняются и отображаются. Markdown в MVP не парсим — экранируем весь ввод как обычный текст |

### NPC
| Ситуация | Поведение |
|---|---|
| Два NPC с одинаковым именем | Разрешено |
| Удаление NPC, на который есть связи | Связи удаляются каскадно, без предупреждения |
| Связь NPC на самого себя | Заблокирована в форме: сам NPC исключён из выпадающего списка |
| Дубль связи между теми же NPC | Разрешён — «брат» и «должен денег» могут сосуществовать |
| Фильтр по тегу, у которого не осталось NPC | Тег пропадает из строки фильтров; если он был активен — сбрасываем на «Все» |
| Тег с пробелами и регистром | Обрезаем пробелы по краям, сравниваем регистронезависимо, храним как ввели |

### Общее
| Ситуация | Поведение |
|---|---|
| Ошибка сети или 500 | Тост «Что-то пошло не так, попробуйте ещё раз». Данные формы не теряются |
| Долгая загрузка данных | Скелетоны, а не спиннер на весь экран |
| Двойной клик по кнопке сабмита | Кнопка блокируется на время запроса |
| Прямой переход на несуществующий адрес | 404-экран с кнопкой на дашборд |
| Мобильный экран | Табы разделов скроллятся горизонтально, сетки схлопываются в одну колонку |

## 7. Валидация: сводка

Все правила проверяются и на клиенте (для UX), и на сервере (для безопасности) одной и той же zod-схемой из общего пакета.

| Поле | Правило | Текст ошибки |
|---|---|---|
| Имя пользователя | 2–40 | «Имя от 2 до 40 символов» |
| Email | формат email | «Проверьте формат email» |
| Пароль | ≥ 8 символов | «Пароль минимум 8 символов» |
| Название кампании | 2–60 | «Название от 2 до 60 символов» |
| Сюжет | ≤ 500 | «Не больше 500 символов» |
| Имя персонажа | 2–40 для игрока; у мастера может отсутствовать | «Имя персонажа от 2 до 40 символов» |
| О себе | ≤ 300 | «Не больше 300 символов» |
| Текст заметки | 1–5000 | «Заметка не может быть пустой» / «Не больше 5000 символов» |
| Имя NPC | 1–60 | «Укажите имя» |
| Тег | 1–24, до 5 штук | «Не больше 5 тегов» |
| Описание связи | 1–60, до 5 связей | «Не больше 5 связей» |

## 8. API

Все ответы — JSON. Авторизация — JWT в httpOnly-cookie, срок 7 дней. Все `/api/campaigns/:id/*` требуют участия в кампании, иначе 403.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | Регистрация + вход |
| POST | `/api/auth/login` | Вход |
| POST | `/api/auth/guest` | Вход в demo-аккаунт из окружения |
| POST | `/api/auth/logout` | Выход |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/campaigns` | Мои кампании |
| POST | `/api/campaigns` | Создать |
| GET | `/api/campaigns/:id` | Кампания + активные участники + моя роль, вычисленная по `ownerId` |
| PATCH | `/api/campaigns/:id` | Изменить (мастер) |
| DELETE | `/api/campaigns/:id` | Удалить (мастер) |
| POST | `/api/campaigns/:id/invite/rotate` | Обновить токен (мастер) |
| GET | `/api/invites/:token` | Превью приглашения (без авторизации) |
| POST | `/api/invites/:token/join` | Вступить + создать персонажа |
| PATCH | `/api/campaigns/:id/me` | Изменить своего персонажа |
| DELETE | `/api/campaigns/:id/members/:memberId` | Мягко исключить (мастер) или выйти (сам): установить `leftAt` |
| GET/POST | `/api/campaigns/:id/notes` | Лента / создание |
| PATCH/DELETE | `/api/campaigns/:id/notes/:noteId` | Автор или мастер |
| GET/POST | `/api/campaigns/:id/npcs` | Список / создание |
| PATCH/DELETE | `/api/campaigns/:id/npcs/:npcId` | Любой участник |
| GET | `/api/health` | Healthcheck для контейнера |

Коды: 400 — валидация, 401 — не авторизован, 403 — нет прав, 404 — не найдено, 409 — конфликт (email занят, уже участник).

## 9. Демо-данные

Судьи откроют ссылку и должны увидеть живое приложение, а не пустой логин. Требования к seed:

- Демо-аккаунт `demo@tavern.app` / пароль на видном месте на экране входа, кнопка «Войти как гость» подставляет их автоматически.
- Одна кампания «Проклятие Штрада» с 4 участниками (у каждого заполнен персонаж), 8 заметками по 3 датам сессий, 10 NPC с тегами двух локаций и одной фракции, 4 связями между ними, назначенной датой следующей сессии.
- Демо-пользователь — игрок, не мастер, чтобы были видны обе роли. Вторая кампания у него же, где он мастер, — чтобы работал переключатель кампаний и был виден блок приглашения.

Seed идемпотентный, запускается при старте контейнера, если база пуста.

## 10. Нефункциональные требования

- Интерфейс на русском языке, локализация вне MVP.
- Адаптив: desktop-first, но все экраны корректно работают от 360px.
- Тёмная тема — вне MVP.
- Доступность: фокус видим на всех интерактивных элементах, у полей есть `label`, у иконочных кнопок — `aria-label`. Полный аудит вне MVP.
- Пароли — argon2. Ввод пользователя экранируется, `dangerouslySetInnerHTML` не используется нигде.
- Rate limit на `/api/auth/*` — 10 запросов в минуту с IP.
- HTTPS обязателен, cookie с флагами `httpOnly`, `secure`, `sameSite=lax`.

## 11. Явно вне MVP

Фотоальбом, загрузка любых файлов, инвентарь, визуальный граф связей, календарь, голосование за дату, реалтайм, комментарии и лайки, поиск, уведомления, восстановление пароля, OAuth, передача прав мастера, роли сложнее «мастер/игрок», markdown, тёмная тема, мультиязычность, экспорт.

Фотоальбом — первый кандидат на добавление, если останется время в субботу. Граф связей — второй, он строится поверх уже существующих данных `NpcRelation` и не требует изменений в модели.
