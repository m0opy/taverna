# Skill: Frontend Architecture

## Цель

Сохранять читаемую FSD-lite архитектуру web-приложения и не возвращать компоненты в единую свалку `pages`.

## Слои

```text
app        bootstrap, providers, router, global composition
pages      route-level screens; сборка widgets/features
widgets    крупные самостоятельные блоки страницы
features   пользовательские действия: login, create campaign, join, edit note
entities   доменные модели и их client-side adapters
shared     UI primitives, api client, config, lib, types
```

Правило импортов: нижний слой не импортирует верхний. `shared` не знает о доменных сущностях, `entities` не знает о страницах, `pages` не содержит повторяемую бизнес-логику.

## Структура файлов

- Компонент и его стили лежат рядом: `Component.tsx` + `Component.module.css`.
- У page-screen своя папка `pages/<page>/ui`, если экран не помещается в один маленький файл.
- Повторяемый UI выносить в `shared/ui`; доменный UI — в `entities/<entity>/ui`; сценарий — в `features/<feature>/ui`.
- Стили по умолчанию пишутся в CSS Modules. Глобальный CSS допускается только для reset, theme tokens и корневых layout-правил в `app`.
- Тесты не класть рядом с production-компонентами в новых изменениях; использовать централизованную структуру, описанную в `docs/testing.md`. Существующие тесты переносить отдельной миграцией.

## Порядок работы

1. Найти ближайший существующий слой и повторить его паттерн.
2. Сначала определить data contract и loading/error/empty состояния.
3. Добавить минимальный UI без нового глобального состояния.
4. Добавить `*.module.css` рядом с компонентом; не использовать inline styles для постоянной стилизации.
5. Проверить импортные границы, responsive поведение и доступность интерактивных элементов.

## Не делать

- не складывать API-вызовы, policy и сложные преобразования прямо в page component;
- не импортировать стили чужой фичи или страницы;
- не создавать универсальный `components/` слой без понятной принадлежности к `shared`, `entities` или `features`;
- не добавлять UI-библиотеку или CSS-in-JS ради одной кнопки.

## Проверка

Запустить затронутые тесты, затем `pnpm check`. Если менялась только визуальная часть, дополнительно проверить чистый browser smoke и отсутствие overflow/сломанных состояний.
