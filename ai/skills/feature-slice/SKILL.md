# Skill: Feature Slice

## Цель

Реализовывать функцию сквозным вертикальным срезом, чтобы contracts, backend, frontend и проверки не расходились.

## Канонический порядок

1. Сформулировать user outcome и out-of-scope.
2. Обновить или добавить Zod contract в `packages/contracts`.
3. Реализовать backend route как HTTP-адаптер; валидацию и доступы держать отдельно от Prisma-запросов.
4. Реализовать service/policy и repository-переиспользование только при необходимости.
5. Добавить API integration tests с реальной тестовой БД для happy path, отказа доступа и ключевого конфликта.
6. Подключить web query/mutation и обработать loading/error/empty/success.
7. Собрать UI по FSD-границам и CSS Modules.
8. Пройти ручной smoke критического пользовательского сценария после refresh.

## Backend boundaries

- `route.ts` отвечает за HTTP, params, auth context и response status.
- `service.ts` отвечает за бизнес-правила и транзакции.
- `repo.ts` отвечает за Prisma-запросы, если они уже не читаются в service.
- Ошибки используют общий error model из `packages/contracts`; не возвращать случайные строки из route.
- Проверять активный membership по `leftAt`, не удалять исторические строки.

## Готовность среза

Срез готов, если контракт покрыт, серверные права нельзя обойти, клиент корректно переживает refresh, проверка проходит, а docs не обещают больше реализованного.

## Scope control

Сначала закрыть P0 happy path и отказ доступа. Не добавлять polish, сложные редакторы и новые абстракции до рабочего сценария. Если функция требует изменения существующего контракта, сначала обновить `api.md` и связанные тесты.
