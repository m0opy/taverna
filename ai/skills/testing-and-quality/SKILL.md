# Skill: Testing And Quality

## Цель

Выбирать самый маленький уровень теста, который надёжно доказывает поведение, и не создавать наборы, которые проходят случайно или не запускаются runner-ом.

## Выбор уровня

- Unit: чистые функции, Zod-схемы, policy helpers и форматтеры.
- API integration: route + auth + Prisma + реальная PostgreSQL для доступа, транзакций и конфликтов.
- Browser smoke/E2E: только сквозные критические сценарии, особенно guest flow и invite между двумя сессиями.

Не мокать функцию, которую проверяет тест. Внешние границы мокать только когда это делает тест детерминированным и не скрывает нужное поведение. Expected values должны быть независимыми от реализации.

## Организация

Целевое правило — централизованный каталог тестов, ориентированный на текущий runner и package boundary. Новые тесты не размазывать по production-компонентам; перенос существующих тестов выполнять отдельной механической миграцией с сохранением discovery.

Каждый тест должен быть независимым, иметь стабильные fixtures и очищать созданные данные. Не оставлять `skip`, `todo` и отключённые проверки без явной причины и ссылки на задачу.

## Минимальный цикл

1. До cleanup найти существующие тесты и зафиксировать защищаемое поведение.
2. Написать тест на observable guarantee, а не на внутреннюю строку вызовов.
3. Запустить затронутый тест локально.
4. Запустить `pnpm check`.
5. Для API-сценариев с БД пройти integration suite с `TEST_DATABASE_URL`.
6. Для release пройти Docker health и ручной чистый browser smoke.

## Отчёт

Указать точные команды и результат, включая количество тестов и skipped tests. Если проверка невозможна, назвать внешнюю зависимость и не выдавать её за зелёный gate.
