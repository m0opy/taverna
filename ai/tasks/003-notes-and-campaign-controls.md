# Task 003: Notes And Campaign Controls

Цель: после Task 002 дать двум участникам кампании полезный совместный сценарий и закрыть основные права доступа.

## Scope

- Notes CRUD: `GET`, `POST`, `PATCH`, `DELETE /api/campaigns/:id/notes`;
- политика заметок: автор редактирует свои, мастер — любые, участник читает все;
- обновление основных полей кампании, rotate invite, kick, leave и delete campaign;
- `PATCH /api/campaigns/:id/me` для имени персонажа;
- страницы `/c/:id/notes` и `/c/:id/settings`, loading/empty/403/404 состояния;
- контракты, policy helpers и API integration tests для прав.

## Acceptance criteria

- участник создаёт заметку, а после перезагрузки она видна всем активным участникам;
- игрок не меняет чужую заметку, а мастер может изменить и удалить её;
- заметки группируются по `sessionDate`, а текст сохраняет переводы строк;
- игрок может покинуть кампанию, мастер может исключить игрока; владелец не может выйти без передачи владения;
- после rotate старый invite не проходит preview/join;
- неучастник получает `403`, отсутствующая сущность — `404`.

## Verification

1. Написать API integration tests на policy заметок и membership actions.
2. Вручную пройти сценарий owner + player в двух браузерных сессиях.
3. Запустить `pnpm check` и локальный Docker health smoke.

## Scope cut order

Сначала убрать polish settings и сложные подтверждения; не убирать Notes CRUD и серверные правила доступа.

## Exit condition

Два реальных пользователя безопасно сотрудничают в одной кампании, а настройки не позволяют обойти роли.
